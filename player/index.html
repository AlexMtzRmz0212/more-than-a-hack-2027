How accurate is the frame number? (read this before trusting a transition)
  • The video is constant 25 fps, so frame n is shown at n/25 s. A label is always looked up with the frame number the video decoder reports as on screen (requestVideoFrameCallback), never with a number the page guessed.
  • Paused, stepping and seeking are frame-exact. A seek aims at the middle of frame n (n + ½)/25 s so rounding cannot land on a neighbour. Labels switch only once the new picture is presented; if the browser lands on a different frame than requested, the number shown is the one actually on screen and a notice says so.
  • While playing, the label can trail the picture by up to one frame (40 ms) because the browser reports a frame when it is composed. If the screen cannot draw every frame, the readout skips frames too; it never shows a label for a frame that was not on screen. To judge a transition, pause and step.
  • Estimated mode. If the browser has no requestVideoFrameCallback, or it goes quiet (some embedded browsers never call it), the frame comes from the playback clock instead: ±1 frame while playing, and the readout says estimated. Paused positions are still checked against the clock after every seek. Use desktop Chrome or Edge for the exact mode.
  • This is the tactical video only. The broadcast recording is not aligned to the submission rows and is not used here.
  • Burned-in clock and the tracking counter are not shown: the label rows come from the frame column of each CSV, which is the video frame index (0-based).
